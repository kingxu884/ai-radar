Embeddings Are Overpriced：16MB 冻结词汇表替代大型 Embedding Table
发生了什么：一篇 arXiv 论文证明，在小语言模型中，通过主成分投影和符号二值化将 Embedding Table 替换为 16MB 的冻结表，在 LAMBADA、HellaSwag 和 PIQA 上几乎不损失性能。
为什么重要：这直接挑战了小模型设计的核心假设。以 Gemma 3 270M 为例，Embedding Table 占据 168M/268M 参数——62.7% 的参数和大部分模型文件大小。如果 16MB 冻结表可以替代，意味着小模型可以在推理端更轻量化、在边缘设备上更高效部署，同时大幅降低量化后的文件体积。这是一个被严重低估的优化空间。
关联动态：与 VAST 开源 EdenLive 世界模型（单消费级显卡跑 720P 24FPS）形成呼应——2026 年的核心叙事之一是“效率压倒规模”。
TokenEconomizer：编码 Agent 的 Token 成本外部控制器
发生了什么：论文提出了一个外部控制器，通过在任务序列中动态决定注入哪些微技能、裁剪哪些无关 token，来降低 Coding Agent 在真实大规模项目中的环境相关 token 成本。
为什么重要：Coding Agent 的成本问题在“单次任务评估”中被系统性地低估了。真实开发者是连续使用 Agent 构建和维护项目的，环境相关的重复 token 消耗会指数级累积。TokenEconomizer 的“外部控制器”思路值得关注——它不修改 Agent 本身，而是在 Harness 层面做成本治理，这种分层架构更易被企业采纳。
关联动态：与 DeepSeek Harness 开源的信号一致：Harness 层正在成为独立的工程层，关注点从“能不能完成任务”扩展到“以什么成本完成任务”。
The Model Knows Better：医疗 Multi-Agent 系统的提示注入防御
发生了什么：论文发现在医疗 Multi-Agent 系统中，单条注入文本在最多 61% 的案例中成功操纵决策，且多智能体协作并不天然提供防御。但模型在被要求“对照患者检查结果核验注入文本”时通常能拒绝。
为什么重要：这是 Multi-Agent 安全研究的关键数据点——协作架构不提供安全冗余，反而可能放大错误共识。但“训练无关的防御策略”（让模型自己核验）的发现很重要，它指向一种轻量级的运行时安全协议，不需要重新训练模型。
关联动态：随着 Multi-Agent 系统在医疗、金融等高风险领域的部署加速，提示注入防御将从学术问题演变为合规要求。这对于 Harness 工程师而言是一个明确的技能缺口信号。
ProPerAgent：记忆驱动的主动辅助范式
发生了什么：论文引入 ProPerMem 基准，研究 Agent 如何从长程个人记忆（平均 618K token）中挖掘证据来决定“是否干预、何时干预、干预什么”。所有基线最多仅达到 15% 的性能。
为什么重要：这标志着 Agent 研究的范式转移——从被动应答转向主动干预。记忆的角色不再只是“提供答案的素材库”，而是“决定是否开口”的决策依据。618K token 的记忆规模和 15% 的基线表现说明这个问题远未解决，是 Harness 工程的下一个前沿。
关联动态：与 MFM（多模态文件系统记忆）论文形成互补——记忆架构正在从单一向量库演变为分层系统（ episodic / spatial / semantic / procedural / working memory ）。
ARBOR：通过推理状态追踪定位长 CoT 中的推理失败
发生了什么：论文提出将推理轨迹表示为“推理状态树”，通过追踪每个步骤创建、验证、剪枝或重新访问哪些状态，来定位推理失败的根源。
为什么重要：当前对推理失败的检测依赖局部信号（文本相似度、单步正确性判断），但 ARBOR 的核心洞察是：一个步骤的贡献取决于之前步骤建立的状态。这种全局视角对于优化 Reasoning Model 的 Post-training（如 RL 奖励设计、推理长度控制）具有直接的工程价值。
关联动态：与 Grokking 论文（Flat Loss, Evolving Features）形成有趣呼应——模型的内部表征演化可能远早于输出改善，需要新的监控方法。

🔬 值得深挖的论文/报告
1. Embeddings Are Overpriced? A Frozen 16 MB Vocabulary for Small and Ternary Language Models（arXiv:2610.22428）
核心贡献：用 PCA 投影 + 符号二值化的 512-bit 冻结编码表替换可训练的 Embedding Table，在 Gemma 3 270M 上训练相同 2.05B token，验证损失仅差 0.20 nats，但下游任务性能几乎持平。
为什么值得读：如果你在构建端侧模型、TinyML 应用或做模型压缩，这篇论文提供了一个完整的“可复现实验设计 + 消融框架”。它回答了一个看似简单但从未被严格检验的问题：那个巨大的 Embedding Table 到底买了什么？答案可能比所有人想的都少。
2. ProPerAgent: Toward Memory-Driven Proactive Assistance（arXiv:2610.22671）
核心贡献：定义了“记忆驱动的主动辅助（MPA）”问题，构建了 ProPerMem 基准（618K token 平均记忆、人工验证的触发窗口、内容和时机的联合评分），并展示了所有基线（包括 frontier 模型）的失败。
为什么值得读：这是目前关于“主动式 Agent”最系统的研究之一。它将“记忆”从被动检索提升为“时机决策”的输入，对于正在设计 Agent 产品的人而言，这篇论文实际上是一份需求文档——它明确了问题边界和评估协议。
3. The Model Knows Better: Defending Medical Multi-Agent Systems Against Prompt Injection（arXiv:2610.22594）
核心贡献：在三个基准、两个系统、两个模型家族上系统评估了医疗 Multi-Agent 的提示注入脆弱性，并发现了一个训练无关的防御方法：引导模型核验注入文本与患者发现的一致性。
为什么值得读：当 Multi-Agent 系统进入医疗场景时，安全性不再是学术讨论而是生死问题。这篇论文的“模型自我核验”防御策略为 Harness 工程师提供了一个可立即实施的运行时防护机制，且论文中的攻击成功率数据可以作为安全评估的参考基线。

为什么今天推荐：表面上看这只是一个 debug 插件的版本更新，但它实际上触及了 Harness 工程中一个核心命题：如何在不调用真实 LLM 的情况下精确模拟 token 使用（包括工具调用、系统提示、推理 token）。在 TokenEconomizer 论文刚刚揭示成本控制重要性的今天，这种工程细节的积累就是竞争壁垒。

• 工具调用和推理 token 的计量需要在 Harness 层精确模拟，否则成本评估永远是黑盒
• debug 插件（echo model）是验证 Harness 逻辑的最小化测试台，不需要真实模型就能测试 token 计数逻辑
• 开源工具的演进路径（从简单回显到完整的 token 计量模拟）反映了 Agent 工程的专业化程度在迅速提升
