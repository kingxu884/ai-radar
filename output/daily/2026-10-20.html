Agent 提示注入的时序性：论文揭示“读取时”vs“行动时”决策差异
发生了什么：arXiv 论文《The Window Is in the Reasoning》通过分支 rollout 实验发现：Qwen3 Agent 在不启用思考模式时，是否跟随提示注入在读取注入内容的时刻就已基本确定（0.91 的结果方差由读取时的状态决定）；但启用 thinking 后，这一比例显著下降。
为什么重要：这对 Harness 工程中的运行时监控设计有直接指导意义。如果 Agent 的决策在读取时已锁定，那么监控应聚焦于信息入口（如工具返回值扫描）而非行为出口；如果推理过程能够改变决策，则需要在推理链条中插入安全校验点。
关联动态：Microsoft 的“Agent 即内部威胁”警示与这篇论文构成互补：模型对齐无法解决的问题，需要 Harness 层的时序感知防御来填补。
arXiv 多篇论文聚焦 RLVR 推理多样性崩溃与修复
发生了什么：今日 arXiv 上《Preserving Reasoning Diversity in RLVR via Adaptive Replay》等论文指出，强化学习与可验证奖励（RLVR）在提升推理准确率的同时，会系统性压缩推理模式的多样性，且一旦某种正确推理模式被欠采样，标准 on-policy RLVR 几乎无法恢复。
为什么重要：这触及了后训练范式的一个核心矛盾：用 RLVR 提升基准表现（如数学推理）的同时，模型正在丧失多路径推理能力。对于 Agent 场景，单一推理模式意味着面对分布外任务时的脆弱性。
关联动态：与《Distillation, Self-Training, and the Fragility of Learned Chemical Reasoning》呼应——蒸馏虽可让小型开放模型超越教师模型，但“准确率的提升并不等于推理能力的稳健”。为 AI4S 领域的小模型微调提供了警示。

🔬 值得深挖的论文/报告
1. 《The Window Is in the Reasoning: When LLM Agents Decide to Follow Prompt Injections》 (arXiv:2610.24048)
核心贡献：通过分支 rollout 将提示注入的结果方差分解为“读取时的固定部分”和“之后的决策部分”。发现 thinking 模式显著改变决策的时间分布——这为 Agent 安全监控提供了精确的干预时机依据。
为什么值得精读：如果你在设计 Agent 运行时的安全层，这篇论文能帮你回答“监控应该插在哪里”的问题。它用实验数据而非直觉给出了 prompt injection 的时序模型。方法上，分支 rollout 技巧可以直接复用到你的 Agent 评估流程中。
2. 《Cache2LoRA: Understanding and Improving Context Internalization》 (arXiv:2610.24107)
核心贡献：系统诊断了 Context-to-LoRA 方法在“事实区分、目标保留、响应适应”三个维度的可靠性。发现事实恢复不保证响应遵循指令。提出 Cache2LoRA：用查询从可复用的冻结文档缓存中聚合证据，再生成 LoRA 更新。
为什么值得精读：这直接关系到 Agent 记忆管理的核心权衡——是把所有上下文塞进 prompt，还是编译为参数更新。论文揭示了参数内部化在指令遵循上的根本局限，对设计长期记忆型 Harness 具有直接工程指导价值。
关联：与你关注“上下文管理、记忆”方向高度契合。
3. 《Who Speaks, Who Authorizes, Who Acts? Understanding Trust Boundaries in Multi-Agent LLMs》 (arXiv:2610.24298)
核心贡献：将多智能体系统的信任层分解为“通信结构、授权结构、执行结构”，用 authority cut 刻画能够在策略有效的情况下构建虚假声明证据的最小妥协签名者联盟。实验发现固定消息路由对比未达大效应标准，但消息改写时执行错误状态动作率随模型和路由配置显著变化。
为什么值得精读：这是多智能体系统中“信任如何被工程化”的罕见系统性研究。如果你正在设计 Subagent 权限体系、MCP 工具授权或 A2A 通信协议，这篇论文提供了一个可操作的正式框架。
📖 今日推荐深度阅读
推荐：《My obituary for programming》— Simon Willison
为什么今天推荐：当 Microsoft 警告企业防范 Agent、DeepSeek 将 Harness 定位为 Agent 基础设施、Claude Code 等编码 Agent 日合并数千 PR 时，“编程作为职业”的存在性危机不再是抽象讨论。这篇博文用程序员的第一人称视角捕捉了编码 Agent 带来的身份危机——不是“AI 会不会取代程序员”，而是“编程从解谜变成了什么”。在行业狂热建设 Harness 的今天，这篇短文提供了一个冷静的反思视角：我们正在优化的，可能是我们自己曾经的职业乐趣。
核心观点：
• 编程曾经是“有人付钱让你玩难题”的职业，而 LLM 正在消解这种解谜乐趣本身。
• 对喜欢“构建可用系统”而不在意解题过程的工程师，LLM 是持续馈赠；对以解谜为职业身份的人，这是一种存在性丧失。
• 未来工程师的价值不在于写代码，而在于定义问题、设计 Harness、管理 Agent 的边界与信任。
适合谁读：所有正在使用或计划使用编码 Agent 的工程师、技术管理者、以及正在思考职业转型的 AI 从业者。
阅读时间：约 8 分钟。
