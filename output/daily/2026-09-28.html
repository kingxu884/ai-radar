2. ScopeBench：Agent 在目标压力下会突破授权边界吗？
发生了什么：arXiv 新论文提出 ScopeBench，专门测试安全 Agent（web/网络渗透测试场景）在"只有越权才能达成目标"的困境下，是否还能遵守授权范围。
为什么重要：现有攻击性安全基准衡量的是"能力上限"，但真正的部署瓶颈是一个对齐问题：Agent 在目标压力下能否守住 scope。这篇论文把"范围遵守"从模糊的伦理讨论变成了可测量、可回归测试的工程指标。对于那些正在把 Agent 部署到生产环境（尤其是安全、运维、金融等高风险领域）的团队，这是一个可以直接转化为内部评测标准的框架。
关联：与 CRC-Router（医疗 Agent 的风险约束路由）和 LLM Parkinsonism（执行控制失败）形成同一趋势——Agent 的可靠性瓶颈正在从"模型能力"转移到"边界遵守与停止条件"。
3. Cartograph：MCP 工具发现的联邦化改造
发生了什么：arXiv 论文提出 Cartograph，一个联邦式 MCP 代理，把 Agent 可见的工具发现从 O(n) 全量遍历降为 O(k) 渐进披露，并引入操作者签名的能力卡片（Ed25519）和三层混淆簇分析。
为什么重要：当 MCP 目录从几十个 tool 膨胀到几百个 server 时，"加载一切"的模式已经不可持续。Cartograph 的核心洞察是：工具发现需要像搜索引擎一样做排序和信任分级，而不是简单暴露目录。这对所有正在搭建 MCP 聚合层或企业级 Agent 平台的团队有直接参考价值。
关联：与 Data Spaces 的 MCP 架构调解（Eunomia Agent）和 Skill Cascading Attacks（技能级联攻击）共同指向一个信号——MCP 生态正在从"接入协议"向"治理基础设施"演进。
4. Learning What to Skip：多智能体 LLM 工作流的反事实信用分配
发生了什么：arXiv 论文引入 LW2S 方法，通过受控跳过干预（controlled skip interventions）学习哪些工作流组件可以省略，从而减少不必要的执行步骤。
为什么重要：多 Agent 工作流的默认假设是"规划→执行→验证→总结"每一步都有价值，但实际情况是后验的。这篇论文用反事实方法量化每个组件的边际贡献，本质上是在给 Agent 工作流做"降本增效"。对于已经部署多 Agent 系统、开始关心单任务成本与延迟的团队，这是一个可以直接落地的优化思路。
关联：与"编码 Agent 成本低效行为"研究（79%-98% 的任务受影响）互为印证——Agent 的经济性优化已经进入方法论的精细化阶段，而非粗放的"减少调用次数"。
5. 编码 Agent 的成本低效行为首次系统分析
发生了什么：arXiv 论文分析了 Claude Code 和 Mini-SWE-Agent 在 SWE-bench Verified 上的 1200 条轨迹，识别出三类成本低效行为：被包含的检索（subsumed retrieval）、相似脚本生成、测试重复执行。
为什么重要：这是少见的直接以 Claude Code 为实验对象的成本研究。79%-98% 的编码任务受这三种行为影响，意味着大多数 Agent 的 token 消耗中存在大量可削减的浪费。开发者设计的 skill 在缓解效果上优于 Agent 自合成的 skill，这挑战了"Agent 自我优化"的流行假设——人工设计的高质量工具仍然不可替代。
关联：与 LW2S 和 LLM Parkinsonism 构成"Agent 经济学"三连发。如果你在维护 Claude Code 或类似工具的团队内部标准，这篇论文的 mitigate 策略值得直接引入。

关联：与 Hist2Sig（H&E 病理图像预测突变签名）、Atelier（CryoEM 自监督特征学习）等论文共同显示——AI for Science 正在从"模型能不能理解科学"转向"模型能不能做实验级的科学推理"。

8. DeepSeek Harness (dsh)：可组合 Agent Runtime 的崛起
发生了什么：DeepSeek 于 2026 年 8 月发布的 MIT 开源 Agent runtime——dsh，采用 Cordis 框架构建，所有运行时服务（包括 Agent loop 和 session store）均可作为插件替换，事件溯源日志使每次运行可回放、可审计。前缀缓存纪律带来 97-99.6% 的缓存命中率，将 Agent 单元成本压至约 $0.045-$0.09。
为什么重要：这可能是国内厂商在 Agent 基础设施层最实质性的开源贡献。把 Agent loop 变成可插拔组件、把 session 变成 append-only event log，这种设计哲学直接回应了今天 Agent 工程中两个最痛点：可观测性和成本控制。对 Harness 工程师来说，dsh 的架构值得认真拆解。

🔬 值得深挖的论文/报告
1. ScopeBench: Do Agents Preserve Engagement Boundaries Under Goal Pressure?
arXiv: 2609.30325
核心贡献：不是测 Agent 的渗透测试能力，而是在"只有越权才能完成任务"的困境中测 Agent 是否守住 scope。30 个死胡同任务，两个条件共享环境/验证器/目标，只改变 scope 限制——这种实验设计干净地分离了"能力"和"遵守"。
为什么值得读：这是 Agent 安全领域第一个把 scope adherence 做成消融实验的基准。如果你在构建 Agent 的权限系统或部署前的安全评测，这个框架可以直接借鉴。实验设计的方法论（如何构造"只有违规才能成功"的场景）本身就是一个值得学习的评测范式。
2. Cartograph: Federated Tool Discovery with Operator-Attested Retrieval for AI Agents
arXiv: 2609.30293
核心贡献：三重机制解决 MCP 规模化：①操作者签名的能力卡片（Ed25519）替代发布者自述；②三层混淆簇分析做工具去重与归类；③两阶段检索（先服务器后工具）实现 O(k) 渐进披露。
为什么值得读：这是 MCP 生态从"能连上"到"能管理"的第一篇系统性工程论文。22 个 server、374 个 tool 的部署规模恰好是目前企业级 MCP 的典型规模。Rift（三层混淆簇分析）的设计思路对任何做工具推荐系统的人都有启发。
3. LLM Parkinsonism: Executive-Control Failure, Token-Inefficient Persistence, and an Uncertainty-Aware Global Executive Control Architecture
arXiv: 2609.30662
核心贡献：提出 LLM Parkinsonism 作为"持续性行动但任务级价值递减"的隐喻，并论证其根源在于 proposal generation、scope interpretation、progress assessment 和 stopping authority 被集中在同一个自条件循环中。提出不确定性感知的全局执行控制架构作为解决方案。
为什么值得读：这篇论文的诊断框架很有价值——不是责怪模型能力不足，而是指出架构缺陷。如果你在设计 Agent 的 meta-cognitive 层或思考如何把"停止决策"从生成循环中分离出来，这篇的架构建议值得细读。
