🔥 今日必读

1. Nvidia：Harness 替代模型成为 Agent 真正的英雄
Nvidia 研究显示，即使底层模型不擅长某任务，只要对 Agent 的 Harness/系统进行微调，就能让 Agent 表现良好且不失控。
为什么重要：这确认了 Agent 性能不只是模型权重问题。上下文管理、工具调用、执行策略和验证逻辑是独立可优化的正交维度。对工程团队而言，与其等下一个更强模型，不如先在 Harness 层建立护城河。
关联：与 DeepSeek“model + harness = agent”路线、SkillGate 的技能选择训练问题直接呼应。

2. Nvidia AVO 在 ARC-AGI-3 达到 100%
NVIDIA AVO 在 ARC-AGI-3 上达到 100%，展示了一个面向长周期自主 Agent 的前沿级通用架构。
为什么重要：ARC-AGI 家族长期被视为抽象推理的试金石。100% 说明该基准正在被 Harness 架构饱和，评估重点需要转向更难的、有状态、长周期、面向真实世界后果的任务。
关联：与 Thinkingbox、FM-Bench 等“有状态评估”基准形成互补；不要用单点饱和基准误判 Agent 能力。

3. SkillGate：技能选择器在长程 Agent 中遭遇“信用饿死”
SkillGate 论文发现，现有 outcome-rewarded RL 无法有效训练 Agent 的技能选择能力。由于序列级优势信号下，选择技能的几个 token 只承担极少的 loss 份额，正确选择常常因为后续执行失败而被错误惩罚。
为什么重要：当技能库/工具库扩大，选择本身成为关键决策。这个问题不解决，工具调用和 Multi-Agent 任务分配会持续不稳定。它指出当前 Agent 训练中一个被忽视的结构性缺陷。
关联：与 RTPO 同天提出，共同指向 Agentic RL 的底层训练困难。

4. RTPO：多轮 Agentic RL 训练不稳定的三个结构性来源
RTPO 论文识别出多轮 Agent 工作流训练中的三类不稳定来源：rollout-training context mismatch、弱 turn 级 credit assignment，以及长短轨迹异步策略漂移。
为什么重要：多轮 Agent 训练比单轮难得多，常见现象是轮数增加后性能严重退化。理解这些根因，是把 Agent 从 demo 推向生产的前提。
关联：与 SkillGate 共同构成 Agentic RL 稳定性研究的当日主线。

5. Thinkingbox：用“后端状态”而不是文本输出评估 Agent
Thinkingbox 是一个 MCP 兼容沙箱，提供隔离工具会话、完整执行轨迹，并以终端后端状态评估结果，包含 507 个策略条件工作流任务。
为什么重要：Agent 在真实业务中必须产生正确的持久状态转换，而不是“看起来对”。基于状态机的评估会过滤掉大量表面成功但实际破坏系统状态的 Agent。
关联：与 Nvidia AVO 在 ARC 上饱和形成对比，企业应引入此类有状态、可审计的评估栈。

6. SWE-bench Science：科学软件工程仍是 Coding Agent 的硬骨头
SWE-bench Science 覆盖 20 个科学领域、98 个 GitHub 仓库、119 个科学软件修复任务。最强 Agent Claude Code with Opus-5 表现仍然有限。
为什么重要：科学代码错误会直接污染科学结论。该基准把 Coding Agent 从通用 SWE 扩展到科研代码修复，揭示失败模式与科学代码特有困难，是 AI4S 落地的关键测量。
关联：与深势科技科研全流程桌面、Eureka 等 AI4S Agent 动态互相对齐。

7. 深势科技：把科研全流程搬进桌面
深势科技展示“科学家只管提问题，AI 负责跑实验”的科研全流程桌面方案。
为什么重要：国产 AI4S 正在从单点计算模型走向 Agent 化科研操作系统。竞争维度从“算得准”转向“读文献—做计算—做实验”的闭环能力。这需要 Agent 与实验数据、文献、计算环境深度耦合。
关联：与 Eureka 的科学发现元 Agent 架构、SWE-bench Science 形成 AI4S 全栈化信号。

8. Eureka：任务条件化 Meta-Agent 架构用于科学发现
Eureka 将长周期任务编译为动态义务图，并在执行中形成具备局部拓扑、验证器和记忆的 Macro-Agents。它完成 170/170 递归任务，生成 3,948 个证书且无假阳性。
为什么重要：面向科学发现的长期任务需要显式接受语义和可验证证书，而不是自由对话。Eureka 展示了规划、验证与架构提升如何在一个可审计框架中组合，对 AI4S 和长程 Agent 设计有参考价值。
关联：与 Thinkingbox 的“可验证状态”思路相通，也与深势科技的科研闭环需求一致。

🔬 值得深挖的论文/报告

1. SkillGate: Training In-Policy Skill Selection in Long-Horizon Agents（arXiv 2608.18852）
核心贡献：识别并命名“selector credit starvation”，证明 outcome-rewarded RL 在长程技能选择上失效，并提出 in-policy 技能选择训练方法。
为什么值得读：技能库/工具选择是当前 Harness 的核心决策。它解释了为什么 Agent 在工具增多时反而容易出错，对设计 Multi-Agent、Subagent 和工具调用策略非常关键。

2. RTPO: Reverse-Turn Policy Optimization for Stabilizing Agentic RL Training（arXiv 2608.18682）
核心贡献：系统分析多轮 Agentic RL 训练不稳定性的三个结构性来源，提出 Reverse-Turn 策略优化方法。
为什么值得读：如果你的团队正在训练或微调 Agent pipeline，这篇论文有助于定位训练崩溃和性能退化根因，尤其适合做 Post-training 和 Agentic RL 的研发同学。

3. SWE-bench Science: Can Coding Agents Resolve Engineering Tasks in Science?（arXiv 2608.19799）
核心贡献：构建首个面向科学研究软件工程的大规模仓库级基准，覆盖 20 个领域、119 个任务，并区分 Issue-driven、Expert-exploratory、Engineering-integration 三类范式。
为什么值得读：如果你关注 AI4S 与开发者工具交叉地带，这篇能告诉你科学代码修复为什么比通用 SWE 更难，以及 Claude Code 等产品的真实边界。

📖 今日推荐深度阅读

推荐：Stop Making TUIs（Simon Willison，2026-08-21）
为什么今天推荐：今天的核心信号是 Agent/Harness 工程正在把真实工具搬进产品。Simon Willison 指出，Coding Agent 已经把“凑合能用的原生 GUI”开发成本压到几乎为零。对 AI 从业者来说，这是重新思考内部工具、Agent 前端和产品原型的时机。
三个核心观点：

  • 编码代理让原生 UI 的成本低到没有理由继续只做 TUI。
  • 原生界面不仅是外观，它会改变你对工具和使用流程的思考方式。
  • 把一个一次性 CLI 转成原生 App 是低成本试错，值得动手。

适合谁读：工程师、独立开发者、AI 产品经理。
预计阅读时间：约 5 分钟。
