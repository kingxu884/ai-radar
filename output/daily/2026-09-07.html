arXiv: 更好的模型可能创造更危险的系统——LLM Agent 在金融市场的相关性风险
论文《Why Better Models Can Create Riskier Systems》通过基于 LLM 交易者的 agent-based simulation 证明：前沿模型的能力提升会导致行为相关性增加，产生不可分散的系统性风险地板。
为什么重要：这对当前 "模型越强→Agent 越好" 的线性假设提出了根本性质疑。当多个 Agent 共享训练数据和架构先验时，它们的"独立性"是幻觉。关联性随能力增长而增强的机制意味着：在金融、风控、内容审核等场景中，部署多个"更强"的模型可能反而增加系统性风险。这是 Agent 生产化部署必须面对的鲁棒性问题。
关联：与《Conformity Breaks Conformal Prediction》形成方法论互补——后者证明多 Agent 系统中的共识会破坏 conformal 校准。两篇论文共同指向一个核心问题：Agent 系统的统计独立性假设在生产环境中不成立。
arXiv: 极稀疏监督激励推理能力——0.05% 的 token 即可匹配全量训练效果
《Extremely Sparse Supervision Incentivizes Reasoning Ability》在 Qwen3 系列上发现：每条推理轨迹仅用 1-2 个 token 的监督信号（占总 token 的 0.05%）就能匹配或超越全 token 训练的效果。
为什么重要：如果这一发现在更广泛模型上可复现，将直接改变 post-training 的经济学。当前 RL/蒸馏流程的大量成本消耗在 token 级监督上，而这个结果暗示：推理能力的激励信号可能高度集中在少数关键决策点（如最终答案前的"信念锚定" token）。对做 reasoning RL 的团队来说，这提供了一个低成本验证路径。
关联：与《ConsensusBench》和《Train What You Deploy》形成一条线：post-training 正从"token 密集"转向"信号密集"，从"环境简化"转向"部署保真"。
arXiv: Multi-Harness RL 的信用分配——Cross-Group 优势池化优于 Within-Group
《What Does Multi-Harness RL Learn?》用 Qwen3-8B 在四个 harness（Aider, OpenHands, Qwen Code, SWE-agent）上做受控实验，对比两种 GRPO 优势分组规则的效果。核心发现：将多个 harness 的奖励池化到同一任务组内（Cross）优于每条 trajectroy 独立分组（Within）。
为什么重要：随着 coding agent RL 规模扩大，训练 harness 的选择和奖励组合方式成为决定性因素。这篇论文首次系统性地隔离了"harness 间奖励池化"这一变量，证明 Cross-group pooling 是提升跨 harness 泛化能力的关键设计。对于正在搭建 Agent RL 基础设施的团队，这是一个可以直接采用的训练策略。
关联：与 DeepSeek Harness 内测的信息直接关联——如果 DeepSeek 的 Harness 部门也在处理类似问题，他们的技术路线选择将影响整个开源生态。
arXiv: τ^τ-Bench——让 Agent 构建本身成为被评估的任务
新基准 τ^τ-Bench 将 "构建生产级 Agent" 作为任务：开发者 Agent 被给予真实业务记录、需求方、生产 API、继承代码库和成本限制，需要交付可运行的 Agent。
为什么重要：现有 Agent 基准测量的是"Agent 执行任务的能力"，但行业正在发生一个转变：Agent 的构建者本身越来越是一个 coding agent。τ^τ-Bench 测量的正是这个元层级的工程能力。这对 Agent 产品化团队意味着：你的评估体系需要开始包含"构建 Agent 的成本与质量"这个维度，而不仅仅是"Agent 运行时的表现"。
关联：与 OpenAI 的 "Research acceleration" 博客形成闭环——当 coding agents 足够强时，它们开始被用来构建更多 coding agents。
arXiv: 训练即部署——Token-Faithful Post-Training 修复 Agent 训练的保真度断裂
《Train What You Deploy》指出现有 coding/terminal agent 的训练管线存在严重的 token 和控制保真度错误：简化训练环境与生产部署不匹配，离线日志重建扭曲原始 prompt 并混淆策略调用与后台操作。提出 C-DPPO 算法解决这一问题。
为什么重要：Agent RL 面临的核心工程问题不是"奖励怎么设计"，而是"训练时的 agent 行为分布与部署时的行为分布是否一致"。这是从模型 post-training 向 agent post-training 迁移时被严重低估的挑战。对正在将 RL 引入生产 Agent 的团队，这篇论文提供了一个可操作的诊断框架和算法改进方向。
关联：与《Multi-Harness RL》形成互补——前者关注 harness 间的奖励池化，后者关注训练-部署环境的保真度。两者合起来构成了 Agent RL 基础设施的两个关键设计维度。

趋势二：Agent 系统的统计独立性假设正在崩塌
证据：《Why Better Models Can Create Riskier Systems》证明前沿模型行为相关性随能力上升；《Conformity Breaks Conformal Prediction》证明多 Agent 共识下 conformal 校准失效；《HarvestBench》测试 Agent 是否愿意付费避免伤害动物。
判断：当模型越来越强、训练数据越来越重叠时，"部署多个独立 Agent 投票"的鲁棒性策略可能正在失效。这不仅仅是安全问题，更是一个经济学问题：如果你部署 10 个"最强模型"做金融决策，它们可能高度相关地犯同样的错误，而你的风险模型假设它们是独立的。未来 3-6 个月，会有更多关于 Agent 系统级风险度量（而非单个模型能力）的研究和产品需求涌现。
启示：金融、医疗、安全领域的 Agent 部署团队需要重新评估 ensemble 策略。模型多样性（不同训练家族、不同架构）可能比单纯的能力分数更重要。
趋势三：Post-training 从 "token 密集" 转向 "信号密集 + 部署保真"
证据：《Extremely Sparse Supervision》证明 0.05% token 即可匹配全量监督；《Train What You Deploy》强调训练-部署保真度；《ConsensusBench》提供规则化过程级信号。
判断：RL/蒸馏的成本结构正在经历重构。如果稀疏监督的发现可泛化，意味着 post-training 的计算瓶颈将从"生成和评分数百万 token"转向"精准定位关键决策点"。同时，"训练环境 = 部署环境"的保真度要求将迫使团队在训练管线中引入更多生产级约束。合起来的效果是：post-training 的进入门槛可能下降（更少的 token 需求），但工程复杂度上升（更高的保真度要求）。
启示：中小团队可以更积极地尝试 reasoning RL，但需要把工程重点放在训练-部署环境一致性上，而不是盲目追求更大的训练数据量。
🔬 值得深挖的论文/报告
1. 《What Does Multi-Harness RL Learn? Credit Assignment and Portability in Coding Agents》
核心贡献：首次在受控条件下隔离了 "harness 间奖励池化" 对 Agent RL 效果的影响。用同一 Qwen3-8B warm start，冻结任务-harness 记录，仅改变 GRPO 的优势分组规则（Within vs Cross），发现 Cross-group pooling 在 held-out harness 上表现更优。
为什么值得读：这是目前关于 Agent RL 基础设施设计最系统的实证研究之一。如果你的团队正在或即将搭建 coding agent 的 RL 训练管线，这篇论文的实验设计可以帮你避免大量试错。特别关注他们对 "sealed SWE-bench Verified oracle" 的使用方式——如何在多 harness 训练下公平评估每个 checkpoint。
适合人群：Agent RL 工程师、post-training 研究员、Harness 基础设施团队。
2. 《Extremely Sparse Supervision Incentivizes Reasoning Ability》
核心贡献：在 on-policy distillation 设定下发现：仅对每条推理轨迹中极少数 token（1-2 个，0.05%）施加监督，就能匹配或超越全 token 监督的效果。在 Qwen3 家族上验证。
为什么值得读：如果这个结果在更大模型和更多任务上复现，它可能改变 post-training 的成本结构和数据标注策略。核心问题：哪些 token 携带了最多的推理激励信号？是最终答案前的"临界 token"还是中间推理步骤？这篇论文提供了实验框架和方法来回答这个问题。
适合人群：Post-training 研究员、RL 工程师、训练成本敏感团队。
3. 《Train What You Deploy: Token-Faithful Post-Training of a Production Coding Agent》
核心贡献：识别了 agent training 中两类保真度错误（token fidelity 和 control fidelity），提出 training coupling framework 和 C-DPPO 算法，通过协商训练协议和封闭失败保证来保障训练-部署一致性。
为什么值得读：这是 "harness 保真度" 问题的首个系统性解决方案提案。如果你曾经在生产中部署过 RL 训练的 agent，你大概率遇到过"训练时表现优秀、部署后行为异常"的问题。这篇论文提供了诊断这些问题的框架。
适合人群：Agent 产品化团队、MLOps 工程师、RL 基础设施架构师。
