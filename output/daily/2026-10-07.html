🔬 值得深挖的论文/报告
What Does a Harness Buy? Tokens, Mostly（arXiv 2610.04433）
核心贡献：首次将“harness 对性能的贡献”与“模型对性能的贡献”严格分离，在 SWE-bench Verified 上比较 Claude Code、mini-SWE-agent、OpenCode 三个生产级 harness 与 5 个模型的交叉组合。
为什么值得读：这是一篇 Harness 工程领域的“基准论文”。它揭示了一个反直觉的发现：harness 之间的性能差异大部分来自 token 消耗量的差异，而非上下文管理策略或工具调用设计的复杂度。如果你正在构建 Agent 系统，这篇论文能帮你避免过度设计。
适合：Agent 工程师、AI 产品经理、技术决策者。
Do Tool Calls Execute as Intended? Measuring and Repairing Intent-Execution Correspondence in LLM Agents（arXiv 2610.04375）
核心贡献：定义“意图-执行对应性”（IEC）——代理发出的工具调用与实际执行操作之间的一致性。研究者通过观察每个“跳”（hop）层接收到的内容，识别出第一个改变调用语义的层。
为什么值得读：这是对 Agent 工具调用链路的“全栈审计”。传统评测只看调用和结果，忽略了中间层（API 网关、解析器、代理框架）对调用的隐性修改。对于使用 MCP 或任何多跳工具调用栈的工程师来说，这篇论文提供了一套可操作的诊断协议。
适合：Harness 工程师、工具调用架构师、MCP 应用开发者。
From Evidence to Action: How Tool-Using Agents Fail（arXiv 2610.07753）
核心贡献：系统分析工具使用代理在“证据-行动”链上的断裂点，覆盖 10 个模型-harness 配置。发现关键失败往往发生在执行之前：代理在调查不完整时就停止，或在必要证据确立之前就行动。
为什么值得读：这是对 Agent 失败模式的“病理学分析”。它不关注最终结果是否正确，而是关注“正确结果是否由正确证据支撑”——这对于金融、法律、医疗等高风险领域尤为重要。如果你在构建需要审计日志的 Agent 系统，这篇论文提供了不良模式分类。
适合：Agent 安全研究者、可靠性工程团队、垂直领域 Agent 产品经理。
