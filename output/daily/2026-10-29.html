1. GitHub Octoverse 2026：AI Agent 工程彻底改写软件开发轨迹
发生了什么：GitHub 2026 年度报告显示，月合并 PR 数量在不到一年内翻了三倍至 2.2 亿，月提交量超 73.8 亿，其中大部分增长集中在下半年。
为什么重要：这不是渐进式增长，而是拐点。当 PR 数量以 3 倍速膨胀而人类工程师数量未同步增长时，唯一的解释是 Coding Agent 已成为主要代码贡献者。这意味着 Harness 工程（而非模型能力）已成为决定团队产出的核心变量——谁能把 Agent 的验证循环、上下文边界、工具调用管好，谁就能获得数量级的产出优势。
与其他动态的关联：LangChain 在 2026 年 2 月公开的案例（仅改 Harness 不变模型，Terminal Bench 从 52.8% 提升到 66.5%）是同样的信号——当下瓶颈在工程层，不在模型层。
2. DeepSeek Harness 团队浮出水面：崔添翼掌舵，Cordis 架构路线确认
发生了什么：Tavily 搜索确认 DeepSeek Harness 团队由前 Jane Street 九年老兵崔添翼领导，核心架构 Cordis 源自 Yifan Shi 的 Koishi 项目，官方招聘明确要求深度熟悉 Claude Code、Codex、Cursor、Manus 等主流 Agent 框架。
为什么重要：这是国内最值得关注的 Agent 基础设施信号。DeepSeek 没有选择在 MCP 生态上做包装，而是从插件动态装卸内核（Cordis）出发自建 Harness，且掌门人来自量化交易的极致工程文化。这条路线如果成功，会产出一个与 Anthropic/Cursor 生态完全不同基因的 Agent 运行时。
与其他动态的关联：与今日 arXiv 上多篇关于 Harness 自我演化的论文（RuHarness、Evolving Agent Teams）形成呼应——行业正在从"静态 Harness"进入"可演化 Harness"阶段。DeepSeek 的招聘规模扩张（计划全部门翻倍）意味着这是国内 Agent 人才最密集的吸入口。
3. Microsoft 首次披露 Azure 实际收入：332 亿美元，OpenAI 贡献 100 亿
发生了什么：微软首次公布 Azure 季度美元收入（332 亿美元），同时披露与 OpenAI 的商业安排（含分成）贡献了 100 亿美元收入。
为什么重要：332 亿意味着 Azure 与 AWS 的差距已缩小到可视范围，而 OpenAI 单独贡献了 Azure 近 30% 的收入——这既是微软 AI 战略的巨大成功，也是极度集中的风险敞口。双方关系的任何波动都会直接动摇微软的财报结构。
与其他动态的关联：同日 Anthropic 在 IPO 前推出 AI 支出透明工具、Google 扩展 AI 搜索广告——三家巨头在同一天释放财务与商业化信号，AI 的基础设施竞赛正在进入"算账"阶段。
4. 扩散模型正式杀入 Agent 主场：350 亿参数，速度比 Jev 快一倍
发生了什么：量子位报道，一个 350 亿参数的扩散模型进入 Agent 场景，声称速度比 Jev 快一倍。
为什么重要：这是对自回归 LLM 在 Agent 领域统治地位的第一轮严肃挑战。如果扩散模型能在离散动作空间上实现真正的并行生成，Agent 的响应延迟将从 token-by-token 解码压缩到近乎常数时间，这对 GUI Agent、工具调用等交互场景是颠覆性的。arXiv 上同期出现的 GUI-JEPA（首个无解码器 GUI Agent 策略）和 Learning to Formalize（用小型形式化器桥接生成与决策）都在指向同一个趋势：Agent 架构正在从"大模型生成一切"走向"生成与决策分离"。
与其他动态的关联：Gemini 4 Carbon 同日宣布全面超越 Opus 5.5 且首发 Token 半价——模型层的竞争依然激烈，但架构层的创新（扩散、JEPA、形式化器）可能比模型尺寸竞赛更能改变 Agent 的经济性。
5. NVIDIA Nemotron 3.5 Transcribe：可 Prompt 的多语言转录模型开源
发生了什么：NVIDIA 发布免费的语音转文字模型，支持 40 种语言转录，最大亮点是"可以用 Prompt 引导和适配"。

与其他动态的关联：与 Google 开放 Gemini 和 Search 给更多应用、Chrome AI 自动填充读取 Gmail 等动态一起，构成了"AI 能力嵌入 OS 和浏览器层"的更大图景——转录、表单、搜索都在被无声地 Agent 化。

📈 趋势分析
趋势一：Agent 架构正在发生"生成-决策解耦"的范式转移
证据链：扩散模型 350B 杀入 Agent 主场（量子位）+ GUI-JEPA 无解码器 GUI 策略（arXiv 2610.36877）+ Learning to Formalize 用小型形式化器桥接生成与决策（arXiv 2610.36595）+ CASEL 的运行时执行选择（arXiv 2610.36570）。
判断：当前 Agent 的主流架构是"大模型逐 token 生成动作"，但这一模式的延迟成本和计算浪费已成瓶颈。四个独立信号同时指向一个方向：把"理解任务并生成候选"与"快速选择执行"分离，前者用大模型、后者用轻量模型或非自回归方法。这意味着 Agent 基础设施的技术栈将出现新的分层——Harness 工程师需要同时理解自回归生成和非回归决策系统的调试方法。预判 6-12 个月内，主流 Agent 框架会引入"候选生成+快速评分"的执行路径。
趋势二：Harness 的自我演化成为 Agent 性能的下一个数量级杠杆
证据链：RuHarness 共同演化 Rubrics 和 Harness（arXiv 2610.36826）+ Evolving Agent Teams 通过中央监督者重组团队逃出局部最优（arXiv 2610.36848）+ LangChain 仅改 Harness 提升 13.7 个百分点 + DeepSeek 招募 Harness 专属团队并扩张全部门。
判断：当模型能力提升的边际收益递减时，Harness 的每个环节——上下文注入策略、验证循环设计、多 Agent 协作结构、记忆管理——都成为独立的性能杠杆。更关键的是，Harness 不再只是工程师设计的静态规则，而正在成为可自我演化的元系统。这解释了为什么 DeepSeek 愿意为 Harness 岗位付高薪：这不是工具链维护，而是核心竞争力的基础设施。
趋势三：AI 行业的商业化重心从"模型能力叙事"转向"财务可核算性"
证据链：Microsoft 首次披露 Azure 实际收入（TechCrunch）+ OpenAI 贡献 100 亿美元（TechCrunch）+ Anthropic 推出支出透明度工具（TechCrunch）+ Google 扩展 AI 搜索广告应对核心广告增速放缓（TechCrunch）+ Anthropic 向投资者披露季度收入近 50% 增长（Simon Willison）。
判断：24 小时内五家巨头同时释放财务信号不是巧合。AI 行业正在经历从"增长故事"到"增长质量"的切换。企业客户不再满足于"AI 能做什么"，而是追问"AI 花的每一美元买到了什么"。对 AI 从业者的启示：拥有"将 AI 能力翻译为业务指标"能力的产品经理和工程师将获得溢价。单纯的算法能力正在让位于端到端的经济性设计能力。
🔬 值得深挖的论文/报告
1. CASEL: Consequence-Aware Selective Execution for Reliable Long-Horizon Tool-Using Agents (arXiv 2610.36570)
核心贡献：提出一个模型无关的运行时分配框架，将校准失败概率、状态依赖后果、可逆性、歧义性和证据新鲜度统一建模，为每个工具调用在"直接执行/验证/沙箱/澄清/审批/弃权"六种模式中进行最优选择。
为什么值得读：这是 Harness 工程中"工具调用安全"维度最系统的形式化尝试之一。大多数 Agent 框架对工具调用的保护要么是全有（直接执行）要么是全无（人类审批），CASEL 给出了一个中间地带的经济学框架。如果你想理解"什么样的工具调用值得花 token 去验证"，这篇是必读。阅读时间约 45 分钟。
2. InfraDev: Can Coding Agents Develop AI Infrastructure, and How Can We Tell? (arXiv 2610.36589)
核心贡献：从 Megatron-LM、vLLM 和 verl 的真实 PR 中提取 36 个跨文件、跨 GPU 的基础设施开发任务，构建了首个针对 AI 基础设施开发的 Agent 评测基准。
为什么值得读：当前的 Coding Agent 评测集中在应用层（网页、API），而 AI 基础设施（训练框架、推理引擎、RL 系统）的开发是更高难度的挑战——需要理解分布式系统、GPU 语义、性能瓶颈。这篇论文不仅是一个基准，更是对"Agent 能否参与核心 AI 系统开发"这一问题的严肃回答。对做 Harness 和 Agent 工具链的工程师尤其有价值。阅读时间约 40 分钟。
3. DiscernMem: Refining Memories and Learning When to Use Them in Multi-Agent Systems (arXiv 2610.36652)
核心贡献：针对多 Agent 系统中的记忆问题，提出两个机制：缺陷感知记忆精炼（通过对比有/无记忆的执行表现来诊断规则缺陷并修复）和边界学习元记忆（记录每条记忆的使用历史和效果，学习何时应该使用、何时应该避免）。
为什么值得读：大多数多 Agent 记忆研究侧重"存什么"，这篇侧重"什么时候用"——这是记忆系统从"数据库"进化为"判断系统"的关键一步。与 RuHarness 和 Evolving Agent Teams 形成了"Agent 自我改进"的完整图景：不是简单的经验积累，而是对经验的批判性评估和情境化应用。阅读时间约 35 分钟。

• Claude Opus 5.5 在 3D 建模、音乐生成和游戏设计三个维度同时实现了质的提升，使得"一个人 + Claude Code"可以完成从概念到可玩游戏的全流程创作
