kw-bench 发布：专攻调查式知识工作的 Agent Harness 基准。
发生了什么：arXiv 新论文 kw-bench 提出一个面向审计、税务、尽职调查等场景的基准，答案已存在但隐藏在不完整、互相矛盾的证据中，测试 Agent 的调查取证能力。
为什么重要：现有 Agent 基准大多是“生成式”——根据 brief 写财务模型或备忘录；但知识工作中最昂贵、最容易出错的是“查证式”任务。该基准直接挑战当前 Harness 作为“写代码工具”的定位，要求 Agent 具备证据召回、冲突消解和可审计推理。它很可能成为下一轮企业级 Agent 产品验收的参照系。
与其它动态的关联：与今天同时出现的 HSC-Bench（任务接管）和《When Retrieval Is Not Enough》（过期事实干扰）形成互补，共同指向一个被低估的问题：Agent 不只是要会生成，还要会“接管状态”和“处理证据污染”。
《When Retrieval Is Not Enough: Obsolete Facts in Agent Memory》指出记忆失败的真正原因。
发生了什么：论文在 MemoryAgentBench 的单跳 FactConsolidation 任务中发现，即使检索结果中已包含最新事实，模型准确率仍从 45% 下降到 32%，原因是陈旧版本的事实与最新事实同时存在并形成竞争。
为什么重要：这打破了“检索到了就能用”的惯性假设。失败不是发生在检索环节，而是发生在记忆融合环节。对于正在构建长期记忆 Agent 的团队来说，必须把“过期事实淘汰”和“冲突消解”作为一等公民，而不是依赖更加庞大的上下文窗口。
与其它动态的关联：该结论与 WAKMan 的 KV Cache 逐出策略研究、CohortFlow 的局部语义修正机制互相印证，说明记忆一致性问题已经从前沿研究进入工程落地阶段。
WAKMan：面向混合流量的 Workload Aware KVCache Manager。
发生了什么：论文测量了生产流量中单轮、多轮和 Agentic 请求对 Prefix Caching 的不同偏好，发现 Agentic 步骤更偏向 recency，而热门 prompt 和长对话更偏向 frequency，没有单一逐出策略能通吃 20 种混合流量。
为什么重要：KV Cache 是推理成本和延迟的核心变量。Agent 工作负载的突发性、多步依赖和频繁前缀复用，使传统 LRU 策略不再适用。这直接影响 vLLM 等推理框架在生产环境中的配置方式。
与其它动态的关联：DeepSeek 正在扩招 Agent 弹性计算研发工程师，说明国内厂商已经把 Agentic 负载的算力调度和缓存策略视为基础设施级问题。
HSC-Bench：首次系统评估 Agent 交接时的状态连续性。
发生了什么：HSC-Bench 用 1,039 个任务评估“任务接管”：接收模型能否恢复仓库证据、延续会话/工具/文件状态，而不只是看最终任务成功率或记忆保留分数。
为什么重要：Multi-Agent 和 Subagent 架构正在普及，但交接失败往往不会在单 Agent 评测中暴露。HSC-Bench 直接把“把活儿交给下一个模型”这件事变成了可测量的工程指标，对编排器设计和上下文打包策略有直接指导意义。
与其它动态的关联：与用户重点关注的 Subagent、Multi-Agent 直接相关，也呼应了《When Retrieval Is Not Enough》中的状态一致性问题。

GlycoWeave：蛋白-聚糖识别的专用扩散模型。
发生了什么：GlycoWeave 在内部坐标空间中建模糖链，集成化学约束构象采样、多尺度表征和多源学习，用于预测蛋白质-聚糖复合物结构。
